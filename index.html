1). GStreamer 파이프라인 구조 설계 및 최적화

다중 RTSP 카메라 영상을 디스플레이·추론용 여러 GStreamer 파이프라인으로 구성하면서, 파이프라인별 디코딩·전처리로 인한 CPU 사용량을 최소화를 목표로 구조를 설계·개선했습니다.

  • SW 디코더 → HW 디코더
    • H.265 스트림 디코딩을 avdec_h265(SW)에서 v4l2slh265dec(HW)로 전환하여 파이프라인을 구축
  • glupload 기반 GPU 전처리
    • 디코딩된 프레임을 glupload로 GLMemory에 올린 뒤 gltransformation / glshader 등으로 rotation·crop·resize를 GPU에서 처리하고, 추론·매칭에 필요한 시점에만 gldownload 하도록 진행
  • 파이프라인 제어·합성 구조
    • 실행제어: valve를 이용하여 스트림을 막는 방식 대신, 파이프라인 상태를 PLAYING/NULL로 실행을 제어
    • 디스플레이 합성: 디스플레이 출력 파이프라인 구성시에 appsrc + input-selector 구조 대신 filesrc + glvideomixer를 두고 각 filesrc pad의 alpha값 설정을 통해 디스플레이 출력 구성

→ 위와 같은 방법들로 인해 라즈베리파이 단에서 RTSP 영상에 대해 GStreamer 파이프라인을 구축하여 디코딩과 전처리를 진행하여 제한적인 라즈베리파이 CM5 보드의 CPU 사용량을 기존대비 약 40% 가량 줄일 수 있었다

2). 애플리케이션 안정화

엣지 환경에서 예외·스레드 장애·네트워크 이슈로 인한 RTSP 단절이 서비스 전체 중단으로 이어지지 않도록 앱 내부 재시도 및 파이프라인 재구성 및 systemd 서비스 등록을 통한 재실행을 구성하였습니다.

  • 프로세스 sys.excepthook / threading.excepthook
    • 메인·데몬 스레드의 미처리된 예외에 대응하여 처음 프로세스 실행 상태로 초기화
  • 파이프라인·런타임 retry
    • GStreamer RTSP ERROR/EOS/timeout 시 파이프라인 재기동을 시도하고, 재시도 한도 초과 시 종료해 상위 재시작으로 넘김
  • systemd 서비스 등록·운영
    • 메인 앱과 시리얼 데몬을 각각 유닛으로 등록(Restart=always), 기동 순서·자동 재시작으로 운영 안정성 확보
